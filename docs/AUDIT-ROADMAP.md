# 项目审查与分阶段路线

最新复审见 [2026-11-04 UI、UX、性能与资源复审](REVIEW-2026-11-04.md)。下文保留 2026-10-16 的历史记录，其中部分待办和环境描述已随后续开发过时；当前优先级与验证结果以最新复审为准。

审查日期：2026-10-16。范围：前端工作区、编辑器、结果网格、SQL/Redis 写入、Rust 三种驱动、连接与事务生命周期、本地保存及验证脚本。

## 判断

项目已有完整的连接、对象浏览、SQL 编辑、多标签、数据编辑及 Redis 基础工作流。下一步应优先补齐数据保真、驱动行为一致性和日常查询复用，再增加分析及管理能力。`src/main.js` 已超过 5,000 行，新增能力应逐步拆到独立模块。

## 第一阶段：本轮已落地

| 范围 | 原问题 | 处理结果 |
| --- | --- | --- |
| 查询复用 | 最近记录仅 10 条，没有独立常用查询库 | 新增最多 200 条收藏，支持选中 SQL 或全文收藏、命名、搜索、重命名、删除、JSON 导入导出、快速操作检索 |
| 执行位置 | 历史查询缺失连接时可能沿用活动连接 | 收藏/历史始终在新标签打开，保留连接 ID、数据库及 Schema；原连接不可用时阻止执行 |
| 草稿恢复 | 支持打开 100 个标签，启动仅恢复 24 个；缺失连接的标签会被删除 | 上限统一为 100；保留缺失连接的 SQL 草稿及原绑定并显示原因 |
| 前端内存 | 已有结果回收函数没有调用，字节数与时间没有记录 | SQL、Redis 命令和 Key 结果均纳入约 24 MiB / 6 份结果预算，优先回收较早的后台结果；保留 SQL、活动结果、未保存单元格及未提交事务 |
| 行写入 | 文本主键 `001` 按数字生成 SQL，可能匹配错误记录；未修改字段也被重写 | 与单元格编辑共用精确字面量；MySQL 使用 UTF-8 十六进制文本；只更新实际修改字段，按真实结果列定位 |
| MySQL 只读 | 仅按首关键词允许读取，后续语句可绕过 | 通过服务端 PREPARE 验证单语句，并在 READ ONLY 事务内执行、结束时回滚清理 |
| MySQL 结果 | 部分结果流没有完整时限、返回大小约束；64 位整数经 JS 数字丢精度 | 读写结果流纳入 30 秒时限及 1,000 行 / 8 MiB 返回上限；整数统一精确十进制字符串，恰好 1,000 行不误报截断 |
| 断开连接 | MySQL 显式事务、Redis 独立控制台未清理，关池可能一直等待 | 清理连接关联会话，先回滚 MySQL 事务再限时关池；事务失败的回滚也有清理时限 |
| 构建 | 样式靠手工列表复制，新增模块容易漏入桌面包 | 自动复制 `src` 下的 CSS，收藏样式进入构建产物 |

主要模块：`src/query-library.js`、`src/query-library-ui.js`、`src/query-memory.js`、`src/workspace-tabs.js`、`src/cell-edit.js`、`src-tauri/src/mysql.rs`、`src-tauri/src/main.rs`。

收藏只保存 SQL 与目标信息，不持久化查询结果。导入先完整验证格式、版本及内容，失败时不部分覆盖；同 SQL + 目标去重，原连接 ID 不按名字重新匹配。导入上限 16 MiB、单条 SQL 上限 100,000 字符。收藏保存失败会保留输入并提示。

结果缓存预算是估算值；受保护的工作超过预算时优先保留工作。它不等同于整个 WebView 的内存上限。

## 第二阶段：可靠性与日常数据操作

建议优先逐项交付以下内容，每项具备独立回归与验收标准：

| 优先级 | 工作项与代码依据 | 验收标准 |
| --- | --- | --- |
| P1 | MySQL 批次执行与事务会话：`mysql::execute_write_conn` 当前只展示首个结果、`statement_count` 固定为 1，批次失败可能部分提交；手写 COMMIT 等不会同步界面事务状态 | 明确批次原子性边界，逐语句展示结果/状态；事务控制统一走受管理会话，DDL 隐式提交单独处理并有真库回归 |
| P1 | 事务内读取一致性：可写模式的事务读取已通过 `execute_mutation` 使用事务会话，但切换只读模式后 `execute_query` 使用独立连接，看不到该事务未提交的写入 | 明确只读切换与事务的关系，同一事务内读写保持会话一致；PG/MySQL 均具备真库测试 |
| P1 | 配置及草稿可靠保存：连接配置直接 `fs::write`，读改写缺少串行保护；`persistTabs` 吞掉保存异常 | 配置原子替换、串行修改、备份恢复；草稿失败提供状态反馈，不展示虚假的已保存状态 |
| P1 | PostgreSQL TLS：`connect_profile` 目前仅接受 `ssl_mode=disable` | 支持证书和主机名校验、自定义 CA；验证成功、未知 CA、错误主机名和证书失败 |
| P2 | 可取消能力：MySQL 不注册当前查询到取消表，停止按钮不能终止服务端查询 | 使用独立控制连接中断原查询，按查询 ID 关联；取消后事务、连接池与下一次查询可恢复 |
| P2 | 稳定分页与服务端筛选：`browseSql` 当前使用无 ORDER BY 的 LIMIT/OFFSET；网格筛选只作用于已加载数据 | 有主键的表默认按完整主键稳定排序；支持选择排序/服务端条件并显示范围；大表逐步接入游标分页，无主键对象明确限制 |
| P2 | 完整行编辑：`openMutation` 仍不支持手工输入主键、空字符串/NULL/DEFAULT 三态 | 新增行可区分生成主键与手工主键；每列三态可见；行保存的异步目标校验与单元格路径统一 |
| P2 | 类型保真及导出：MySQL `Bytes` 当前用 UTF-8 容错解码，BLOB 会失真；目前导出仅 CSV | 返回列类型及二进制编码，支持 BLOB 查看/下载；增加 JSON、INSERT 导出及列/行范围选择，覆盖大整数、NULL、空串、换行与二进制 |

## 第三阶段：SQL 分析与开发效率

1. **执行计划查看器**：先做 PostgreSQL/MySQL EXPLAIN 的结构化树与耗时/扫描量提示。会真正执行查询的 ANALYZE 单独确认，先只开放安全读取。
2. **参数化查询与模板**：在现有收藏上增加参数定义、类型和执行前输入，使用驱动参数绑定，避免手工拼 SQL。
3. **结构管理增强**：补索引/约束/外键编辑及依赖展示；MySQL 补过程、函数、触发器和事件目录；结构差异预览后生成可审阅 SQL。
4. **工作区与历史**：收藏分组/标签、执行耗时与状态记录、历史按连接/时间筛选；逐步拆分连接、查询执行、对象操作与持久化控制器。

验收要求：保持目标库绑定；错误保留编辑草稿；浅色、深色和最小窗口可用；分析与结构操作具有真实数据库回归。

## 第四阶段：Redis 与连接扩展

1. Redis hash/set/zset/stream 游标分页与加载更多。当前 `get_value` 固定首 500 项，部分 SCAN 游标未返回，不能继续查看大 Key。
2. Redis TTL 查看/修改、类型化编辑和批量操作预览，所有读取统一超时及返回字节预算。当前部分 `get_value` 分支直接等待服务端，字符串和控制台也需额外大小控制。
3. SSH 隧道、连接分组和按环境标识；再评估 Redis Cluster/Sentinel。先建立各驱动公共的连接、取消、错误和会话生命周期契约。
4. CSV/JSON 数据导入向导：字段映射、预览、校验、事务策略与逐行错误反馈，随后才考虑更多数据库适配器。
